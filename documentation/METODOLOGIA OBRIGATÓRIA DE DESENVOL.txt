METODOLOGIA OBRIGATÓRIA DE DESENVOLVIMENTO
==================================================================

IMPORTANTE:
O jogo NÃO deve ser desenvolvido inteiro de uma vez.

O desenvolvimento deve seguir:
- arquitetura modular;
- desenvolvimento incremental;
- testes constantes;
- validação contínua;
- construção em blocos independentes.

Objetivo:
- evitar caos;
- evitar bugs exponenciais;
- manter consistência;
- manter performance;
- manter código limpo;
- facilitar expansão futura.

==================================================================
FILOSOFIA DE DESENVOLVIMENTO
==================================================================

A prioridade NÃO é quantidade de conteúdo.

A prioridade é:
- gameplay divertida;
- responsividade;
- fluidez;
- sensação boa de jogar;
- estabilidade;
- performance.

REGRA PRINCIPAL:
“Se não estiver divertido com pouco conteúdo,
não ficará divertido com muito conteúdo.”

==================================================================
DESENVOLVIMENTO EM BLOCOS
==================================================================

Cada sistema deve ser:
1. criado;
2. testado;
3. refinado;
4. estabilizado;
5. expandido.

NUNCA:
- gerar tudo de uma vez;
- criar dezenas de sistemas simultaneamente;
- adicionar efeitos antes do gameplay funcionar.
